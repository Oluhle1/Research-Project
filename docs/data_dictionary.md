# Supported upload contract

Version `opg-screen-v1` supports **normalized research records for KwaZulu-Natal in October 2014–October 2015**. It is not an arbitrary-dataset importer and does not express current grant policy. Every upload requires the complete column set below. Column order may vary; extra columns are blocked. UTF-8 CSV, including a UTF-8 BOM, is accepted, with limits of 20 MiB and 50,000 records.

The downloadable template is generated by `opg_core.schema.synthetic_template()`. All its records are invented. `from_research_people()` is a **local verification helper only**: it filters the existing source pipeline to KZN and retains original keys in memory. Never publish or commit its result.

| Column | Accepted content / meaning |
| --- | --- |
| `schema_version` | Exactly `opg-screen-v1` |
| `context` | Exactly `LCS_KZN_2014_2015`; compatibility is an assertion by the uploader, not external validation |
| `record_id` | Unique synthetic/pseudonymous identifier, 1–128 characters; starts with a letter/digit and otherwise uses letters, digits, `_`, `.`, `:`, `-` |
| `household_id` | Same identifier syntax; shared by household members to resolve spouse links; excluded from screening output |
| `personno` | Integer 1–27; leading zeros normalize away; household/person keys must be unique |
| `survey_year`, `survey_month` | Integer year/month in October 2014 through October 2015 |
| `province_code` | Exactly `5` (KwaZulu-Natal) |
| `age` | Required completed age, integer 0–105; age below 60 is out of the study frame |
| `sex` | `1` male, `2` female, or blank predictor value |
| `marital` | `1` married; `2` living together; `3` never married; `4` widowed; `5` separated; `6` divorced; `9` unspecified |
| `partner_in_hh` | `1` resident, `2` nonresident, `8` not applicable, `9` unspecified |
| `spouse_no` | Person pointer 1–27; `88` not applicable; `99` unspecified; blank normalizes to `99` |
| `schooling_raw` | Codes 1–32, 98, 99, or blank. Codes 1–7 and 98 are below Grade 7; 8–20 and 23–30 are Grade 7 or above; 21, 22, 31, 32, 99 and blank are model missing |
| `settlement` | `1` urban formal; `2` urban informal; `4` traditional; `5` rural formal; blank is model missing |
| `welfare_distance` | `1`–`4` nearer than 5 km; `5`–`7` at least 5 km; `8` unavailable, grouped with far; `9`, `99`, blank are model missing |
| `person_weight` | Required finite positive survey person weight; use 1 for synthetic examples |
| `any_grant` | `1` yes; `2` no; `3` don't know; `9` unspecified |
| `oldage`, `disability`, `child`, `caredep`, `foster`, `warvet`, `inaid` | Each is `1` yes; `2` no; `8` not applicable; `9` unspecified |
| `private_income` | Annual nominal private-income proxy after documented social-assistance exclusions; finite nonnegative amount or blank when unresolved |
| `opg_income` | Preceding-year annual OPG income; finite nonnegative amount or blank when unresolved |
| `income_schedule` | One of `supported_zero`, `summed`, `absent`, `unspecified`, `contradiction` |

Amounts and weights above 10¹² are outside this bounded prototype contract. Unknown codes and nonfinite amounts block processing; model missing values receive warnings and require the frozen training preprocessing. Blank screening responses normalize to unspecified code `9`, preserving unresolved screening rather than assuming “no”. The existing historical screen's valid not-applicable code `8` remains unchanged.

`supported_zero` requires **both supplied amounts to be exactly zero**. `summed` requires both amounts, including an explicitly supplied zero where applicable. `absent`, `unspecified` and `contradiction` require both amounts blank. No validator fills missing income with zero. The normalized stage does not accept raw COICOP rows; source aggregation and unknown-source verification belong to the optional three-table importer.

The previous `cohort_person.csv` is a derived research output, not this upload schema: it omits raw grant answers needed to rerun screening. Uploading only the 1,013 final cohort cannot recover the remaining older-adult outcomes. For full screening, include household members required by resident spouse links, even when they are under 60. A missing resident spouse is reported unresolved.

Validation errors name known columns and aggregate invalid-row counts without echoing uploaded identifiers, values or unknown header text. Identifiers beginning with spreadsheet formula markers are blocked. Original IDs may be used inside controlled local parity checks; reports must replace internal `record_id` with safe pseudonyms. Survey microdata, household pointers and source IDs are not public demo material.
